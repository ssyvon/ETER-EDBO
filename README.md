# ETER / EDBO

Репозиторій містить пайплайни, підготовлені таблиці, ноутбуки та графіки для аналізу даних ETER і EDBO щодо закладів вищої освіти.

## Логіка проєкту

Проєкт розділяє два джерела даних:

- `ETER` - європейські дані про заклади вищої освіти, студентів, персонал і фінанси.
- `EDBO` - українське вивантаження щодо закладів, регіонів, спеціальностей, форм навчання та джерел фінансування.

Сирі файли зберігаються в `data/raw/` і не редагуються напряму. Усі очищені, агреговані та проміжні таблиці створюються пайплайнами в `data/processed/`. Ноутбуки використовують `data/processed/` як основне джерело даних і відповідають за аналіз та візуалізації.

ETER і EDBO не змішуються в одному ноутбуку без явного розділення цілей, джерел і результатів.

## Структура

```text
.
├── data/
│   ├── raw/                 # вихідні файли, не змінювати вручну
│   └── processed/           # очищені дані, агрегати, перевірки, аналітичні таблиці
├── figures/                 # усі згенеровані графіки та експортовані зображення
├── notebooks/               # аналітичні Jupyter-ноутбуки
├── scripts/                 # відтворювані пайплайни підготовки даних
├── requirements.txt         # Python-залежності
└── README.md
```

## Джерела та основні артефакти

Для ETER первинними аналітичними таблицями є:

- `data/processed/df_base.csv`
- `data/processed/df_base_clean.csv`
- `data/processed/eter_institution_metrics.csv`
- `data/processed/country_profiles.csv`
- `data/processed/country_overview.csv`
- агрегати за країнами, студентами та фінансами з `data/processed/`

Для EDBO первинними аналітичними таблицями є:

- `data/processed/edbo_prepared.csv`
- `data/processed/edbo_*_summary.csv`
- `data/processed/edbo_*_checks.csv`
- `data/processed/edbo_inconsistent_row_sums.csv`

## Пайплайни

`scripts/01_eter_pipeline.py`:

- читає `data/raw/ETER_fullDump_27042023.csv`;
- вибирає потрібні колонки та перейменовує їх у стабільний snake_case формат;
- замінює спеціальні коди ETER на пропуски в аналітичних полях;
- створює `df_base.csv`, `df_base_clean.csv`, `eter_institution_metrics.csv`;
- рахує країнові профілі, метрики доступності, перевірки якості й таблиці винятків.

`scripts/02_edbo_pipeline.py`:

- читає `data/raw/edbo_raw.xlsx`;
- приводить студентські показники й коди до числових типів;
- розраховує бюджетних, контрактних, денних, заочних і вечірніх студентів;
- перевіряє узгодженість рядкових сум;
- створює `edbo_prepared.csv` і підсумкові таблиці за регіонами, закладами, ступенями, спеціальностями, формою власності, підпорядкуванням, формою навчання та джерелами фінансування.

## Ноутбуки

Наявні ноутбуки:

- `notebooks/01_ETER_EDA.ipynb` - первинний EDA для ETER на основі підготовлених таблиць.
- `notebooks/02_EDBO_EDA.ipynb` - EDA для EDBO: якість даних, регіони, заклади, ступені, спеціальності, форми навчання, бюджет/контракт.
- `notebooks/03_median_ corelation.ipynb` - альтернативний ETER-аналіз розподілу ЗВО за кількістю студентів і медіанних кореляційних показників.
- `notebooks/04_corelation.ipynb` - кореляційний аналіз на рівні окремих ЗВО для 2022-2023 років.

Увесь Markdown у ноутбуках має бути українською мовою.

## Фігури

Усі згенеровані фігури, графіки, діаграми та експортовані зображення потрібно зберігати безпосередньо в репозиторному каталозі `figures/`.

Не створюйте окремі підкаталоги для ноутбуків на кшталт `figures/01/`, `figures/02/` або `figures/03/`. Не зберігайте візуальні артефакти в `notebooks/`, `notebooks/models/figures/`, `data/` чи інших внутрішніх каталогах.

Назва кожної фігури має починатися з номера ноутбука:

- `figures/01_eter_coverage_by_year.png`
- `figures/02_edbo_region_summary.png`
- `figures/03_model_comparison.png`
- `figures/04_students_students_per_teacher_scatter_2022_2023.png`

## Відтворення середовища

Створіть і активуйте віртуальне середовище:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Запустіть пайплайни підготовки даних:

```bash
python3 scripts/01_eter_pipeline.py
python3 scripts/02_edbo_pipeline.py
```

Після цього відкривайте ноутбуки з `notebooks/` і запускайте їх у порядку, що відповідає номеру в назві.

## Перевірки перед завершенням змін

Перед завершенням змін у ноутбуках потрібно перевірити:

- `.ipynb` файл є валідним JSON;
- ноутбук виконується без помилок;
- усі нові або оновлені фігури збережені в `figures/`;
- назви фігур мають правильний номерний префікс: `01_`, `02_`, `03_`, `04_` тощо;
- Markdown-комірки написані українською;
- аналіз використовує `data/processed/`, якщо завдання явно не вимагає `data/raw/`.

Приклад перевірки JSON:

```bash
python3 -m json.tool notebooks/01_ETER_EDA.ipynb >/dev/null
```

## Правила роботи з даними та службовими файлами

Не змінюйте сирі дані в `data/raw/` напряму. Якщо потрібні очищення, агрегації або проміжні результати, додайте їх до пайплайна та збережіть у `data/processed/`.

Не додавайте до проєкту службові кеші, тимчасові файли або системні артефакти:

- `.matplotlib-cache`
- `.ipynb_checkpoints`
- `.DS_Store`
- тимчасово виконані копії ноутбуків
- `__pycache__/`
- `*.pyc`

Якщо створюється новий ноутбук, його назва має починатися з номера, наприклад `05_new_analysis.ipynb`.
